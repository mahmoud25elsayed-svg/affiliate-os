# دليل التعامل مع الحوادث: تسريب أو خرق البيانات الشخصية (Data Breach)
## Runbook: Incident Response — Personal Data Breach & Egyptian Law 151/2020 Compliance

> **درجة الخطورة:** حرجة للغاية (Sev-1 Critical — Legal & Regulatory Liability)  
> **زمن الاحتواء التقني:** أقل من ساعة واحدة  
> **الالتزام القانوني الإلزامي:** إبلاغ السلطات المختصة والأطراف المتضررة خلال **72 ساعة**  
> **الفريق المسؤول:** مدير المنصة التنفيذي، المستشار القانوني، ومهندس أمن المعلومات (CISO / DPO)

---

### 1. الإطار التشريعي المصري الحاكم (Legal Compliance Framework)

تخضع منصة AffiliateOS وبشكل ملزم لأحكام **قانون حماية البيانات الشخصية المصري رقم 151 لسنة 2020** ولائحته التنفيذية.
تنص **المادة (7)** من القانون صراحةً على ما يلي:
> "يلتزم كل من المتحكم والمعالج، في حال حدوث أي خرق أو تسريب للبيانات الشخصية، بإخطار **مركز حماية البيانات الشخصية** خلال **72 ساعة** من تاريخ علمه بالواقعة، كما يلتزم بإخطار الشخص المعني بالبيانات فوراً إذا كان الخرق من شأنه تعريض حقوقه أو حرياته أو سلامته للخطر."

---

### 2. الأعراض ومصادر الرصد (Detection & Symptoms)

1. **رصد وصول غير مصرح به لقواعد البيانات أو النسخ الاحتياطية:**
   * محاولات تصدير كتلية غير معتادة لبيانات العملاء أو المسوقين (Mass Data Export).
   * ظهور سجلات المنصة أو بيانات العملاء في منتديات عامة أو قواعد بيانات مسربة.
2. **اختراق مفاتيح التشفير أو أسرار الخادم:**
   * تسريب ملف `.env` أو مفتاح التطبيق `APP_KEY` أو بيانات الاتصال بقاعدة MySQL.
3. **ثغرات أمنية مستغلة بنجاح:**
   * استغلال ثغرة حقن أو كسر لعزل المستأجرين (Tenant Isolation Bypass) أدى إلى تسرب بيانات متجر إلى متجر آخر.

---

### 3. إجراءات الاحتواء الفوري التقني (Technical Containment — أول 60 دقيقة)

1. **عزل النقطة المخترقة وتجميد الدخول:**
   * حظر عنوان الـ IP المهاجم فوراً عبر جدار الحماية (IP Tables / Cloudflare / Hostinger Firewall).
   * إلغاء وتجديد كافة جلسات المستخدمين فوراً:
     ```bash
     php artisan session:clear
     ```
2. **تدوير وتغيير كافة الأسرار ومفاتيح البيئة فوراً (Credential Rotation):**
   * تغيير كلمة مرور قاعدة بيانات MySQL في `hPanel` وتحديثها في ملف `.env`.
   * تدوير وتغيير مفاتيح بوابات الدفع (Paymob HMAC Secret) وبوابات الرسائل النصية (SMS Gateway API Keys).
   * تدوير مفاتيح التشفير والـ SSH Keys للخادم.
3. **التحقق من سلامة كود المنصة:**
   * فحص تطابق كود الخادم مع فرع `main` الموثق على GitHub للتأكد من عدم حقن أي ملفات ويب شل (Webshells):
     ```bash
     git status
     git diff origin/main
     ```

---

### 4. التحقيق الجنائي وتحديد نطاق الضرر (Forensic Investigation)

1. **حصر نوع وعدد السجلات المتأثرة بدقة:**
   * هل شمل التسريب:
     * أسماء وأرقام هواتف وعناوين العملاء؟
     * مستندات التحقق من الهوية (KYC) للمسوقين؟
     * سجلات الأرباح والتحويلات المالية؟
2. **فحص سجلات العمليات والـ Consent Logs:**
   * مراجعة استعلامات جدول `consent_logs` و `activity_log` لتحديد توقيت ومدى الاختراق.
3. **توثيق الأدلة الجنائية:**
   * حفظ نسخ كاملة غير قابلة للتعديل من سجلات الخادم `storage/logs/` و `access_log` لاستخدامها في البلاغ الرسمي.

---

### 5. الإجراءات القانونية الإلزامية خلال 72 ساعة (Mandatory Legal Notifications)

#### أ. إخطار مركز حماية البيانات الشخصية المصري (رسمياً خلال 72 ساعة)
يجب إعداد تقرير رسمي وتقديمه للمركز متضمناً:
1. طبيعة ووقت اكتشاف واقعة التسريب.
2. الفئات التقريبية للبيانات المتسربة وعدد الأفراد المتأثرين.
3. الآثار والمخاطر المحتملة الناتجة عن الواقعة.
4. الإجراءات الفورية التي اتخذتها المنصة لاحتواء الخرق والحد من آثاره.
5. اسم وبيانات الاتصال بمسؤول حماية البيانات (DPO) بالمنصة.

#### ب. إخطار الأشخاص المعنيين (التجار والمسوقين والعملاء)
في حال تضمن التسريب بيانات قد تعرض المستخدمين للخطر، يجب إرسال إشعار فوري وشفاف بالبريد الإلكتروني والرسائل النصية يتضمن:
1. شرح مبسط لما حدث وبدون تهوين أو مبالغة.
2. البيانات التي تأثرت تحديداً (مثل رقم الهاتف أو العنوان).
3. التأكيد على عدم تسريب بيانات البطاقات الائتمانية (حيث تعالج عبر بوابات مشفرة خارج خوادم المنصة).
4. الإجراءات الاحترازية المطلوبة من المستخدم (مثل تغيير كلمة المرور فوراً وتفعيل 2FA).

---

### 6. خطة التعافي والوقاية الدائمة (Post-Breach Hardening)

1. إجراء تدقيق أمني شامل للكود مقابل معايير OWASP عبر جهة أمنية معتمدة مستقلة.
2. إعادة تقييم صلاحيات الوصول والتأكد من تطبيق مبدأ الحد الأدنى من الصلاحيات (Least Privilege).
3. مراجعة وثائق الامتثال والسياسات الداخلية وفق متطلبات الجهاز القومي لتنظيم الاتصالات (NTRA).
