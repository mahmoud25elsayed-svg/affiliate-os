**الموقع:** https://mediumseagreen-rat-742689.hostingersite.com/

**نوع الاختبار:** اختبار فعلي شامل (وظيفي، تكامل، أمان، أداء، توافق) على بيئة الاستضافة

## 0. الإطار العام

### 0.1 نطاق النظام (ما سيُختبر)
منصة SaaS متعددة المستأجرين (multi-tenant) للتجارة الإلكترونية والتسويق بالعمولة في مصر:
- موقع تسويقي عام (الرئيسية، الميزات، الأسعار، الأسئلة الشائعة، المدونة، تواصل معنا)
- تسجيل التاجر مع تحقق OTP عبر الهاتف وإنشاء متجر على نطاق فرعي
- محرك المتجر (Lunar): المنتجات، السلة، الطلب بالدفع عند الاستلام (COD)
- نظام الأفلييت: روابط التتبع، إسناد آخر نقرة (Last-Click)، العمولات، المدفوعات
- الكول سنتر: طابور الطلبات، قفل المكالمة، جدولة المتابعة، تأكيد الطلبات
- الشحن: إنشاء البوليصة، تحديث الحالة عبر Webhooks، المرتجعات
- دفتر الأستاذ المحاسبي (القيد المزدوج) وتسوية تحصيل COD
- الاشتراكات والباقات وحدودها، وتجربة مجانية لمدة 14 يوماً
- REST API والنطاق المخصص (Custom Domain)
- صفحة الحالة `/health`

### 0.2 الأدوار التي تحتاج حسابات اختبار
| الدور | الحسابات المطلوبة |
|---|---|
| مدير المنصة (Super Admin) | 1 |
| تاجر (Merchant / Store Owner) | 3، واحد لكل باقة (البداية، المحترف، المؤسسات) |
| موظف كول سنتر | 2 على نفس المتجر، لاختبار القفل والتزامن |
| مسوق بالعمولة (Affiliate) | 2 على نفس المتجر، لاختبار الإسناد |
| عميل نهائي (زائر المتجر) | جلسات مختلفة / متصفحات مختلفة |

### 0.3 بيانات الاختبار
- أرقام هواتف مصرية للاختبار (010/011/012/015)، ويفضل أن تكون أرقاماً حقيقية تحت سيطرتك لاستقبال OTP
- عناوين في محافظات مختلفة، منها القاهرة وأسوان وشمال سيناء، لتغطية الـ 27 محافظة
- منتجات بأنواع مختلفة: بسيط، له متغيرات (variants)، مخزون صفر، سعر بكسور
- أسماء ونصوص عربية وإنجليزية ورموز خاصة وإيموجي

### 0.4 الأدوات
- المتصفحات: Chrome وFirefox وSafari (iOS) وSamsung Internet
- DevTools وLighthouse لفحص الأداء وإمكانية الوصول
- Postman أو curl لاختبار REST API والـ Webhooks
- OWASP ZAP (فحص سلبي فقط) لفحص الأمان
- k6 أو JMeter لاختبار حمل خفيف، بعد موافقة الاستضافة
- جدول (Excel أو Sheets) لتسجيل الحالات والعيوب

### 0.5 تصنيف خطورة العيوب
| المستوى | التعريف | مثال |
|---|---|---|
| حرج (P0) | توقف وظيفة أساسية، أو فقدان أموال أو بيانات، أو ثغرة أمنية | تاجر يرى طلبات تاجر آخر، أو قيد غير متوازن |
| عالٍ (P1) | وظيفة رئيسية معطلة ولها حل التفافي صعب | صفحة الدخول 404 |
| متوسط (P2) | خلل وظيفي جزئي | حدود الباقة لا تُطبّق |
| منخفض (P3) | شكل أو نص أو ترجمة | ظهور "-1" بدل "غير محدود" |

### 0.6 معايير البدء والانتهاء
- **شرط البدء:** صفحة `/health` تعمل، ووجود حساب Super Admin، ووجود تأكيد بأن هذه البيئة بيئة اختبار وليست بيانات عملاء حقيقيين.
- **شرط الانتهاء:** تنفيذ 100% من حالات P0 وP1، وعدم وجود عيب حرج مفتوح، وتوازن دفتر الأستاذ في كل السيناريوهات.

### 0.7 قواعد السلامة أثناء الاختبار
- لا تُرسل OTP بكثافة لأرقام حقيقية لا تملكها. كل رسالة SMS لها تكلفة.
- اختبارات الحمل والأمان النشط تتم بعد إذن، ولا تتم على الإنتاج.
- لا تُنشئ شحنات حقيقية مع شركات الشحن إلا عبر وضع sandbox.

|---|---|---|
| O-1 | روابط القائمة والشعار والفوتر تشير إلى `https://127.0.0.1/...`. السبب على الأرجح أن `APP_URL` غير مضبوط | P1 |

| O-8 | `/health` عام ويكشف معلومات داخلية: حجم التخزين، وحالة الطابور، وحالة تدقيق الدفتر | P2 أمان |

| AF-02 | توليد رابط تتبع لمنتج ورابط عام للمتجر | الرابط يعمل ويضع كوكي التتبع |

## 18. الجزء السابع عشر: الاختبار الشامل من البداية للنهاية (E2E) والقبول
**المدة:** يوم واحد. يُنفذ بعد إصلاح عيوب الأجزاء السابقة.

**سيناريو E2E-01 (الدورة الكاملة):**
1. تاجر جديد يسجل ويتحقق بـ OTP ويُنشأ متجره
2. يضيف 3 منتجات ورسوم شحن ويضيف موظفَي كول سنتر وأفلييت اثنين
3. عميل يدخل من رابط الأفلييت A ثم B، ثم يطلب COD
4. الكول سنتر يؤكد الطلب، ويمنع القفلُ الموظفَ الثاني
5. تُنشأ بوليصة شحن، ثم Webhook بالشحن، ثم Webhook بالتسليم
6. تسوية تحصيل COD
7. **التحقق:** الطلب منسوب إلى B، والعمولة مستحقة له، والمخزون صحيح، والقيود متوازنة، والتقارير متطابقة

**سيناريو E2E-02 (المرتجع):** مثل السابق، لكن يرفض العميل الاستلام. التحقق: العمولة ملغاة، والمخزون عائد، والقيود عكسية.

**سيناريو E2E-03 (حدود الباقة):** تاجر على باقة البداية يصل إلى الطلب رقم 100، ثم يرقّي إلى المحترف، فيستمر العمل.

**بعدها:** اختبار انحدار (Regression) لحالات P0 وP1 بعد كل دفعة إصلاحات.

## 20. التوثيق والتقارير

**صيغة تسجيل العيب:**
`ID | العنوان | الجزء | الخطورة | خطوات إعادة الإنتاج | النتيجة الفعلية | النتيجة المتوقعة | لقطة شاشة أو فيديو | المتصفح والجهاز | الدور | الحالة`

**المخرجات:**
- جدول حالات الاختبار مع حالة كل حالة: نجح، أو فشل، أو محجوب، أو لم يُنفذ
- سجل العيوب مصنفاً حسب الخطورة
- تقرير يومي مختصر: ما نُفذ، وما فشل، وما يعطل التقدم
- تقرير ختامي يتضمن توصية: جاهز للإطلاق أم لا، وشروط الإطلاق
